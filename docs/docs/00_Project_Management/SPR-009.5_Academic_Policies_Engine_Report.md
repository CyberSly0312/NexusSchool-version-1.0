# Summary

SPR-009.5 delivers the **Academic Policies Engine**, the exclusive origin of
academic rules mandated by ARCHITECTURE_DECISIONS §6. Before this sprint the
engine existed only as two empty stub adapters (Report Card and Academic
Communication); the governance reconciliation of the same day corrected its
status from "Complete" to "Planned / Not Started" precisely because no
implementation existed. This sprint implements it.

The engine is a new bounded context, `App\Domains\AcademicPolicy`, built to the
same DDD contract conventions as the Academic Intelligence engines (SPR-010 —
SPR-013): pure Domain, final Application actions/services, Infrastructure
persistence, Filament presentation, tenant isolation on every path, and a typed
value store with strict validation. The two existing stub adapters are rewired
to the new engine through a dedicated query contract, so Report Card and
Academic Communication now read policies from the database instead of `[]`.

**Design boundary (deliberate, documented):** the engine is the *store and
distribution layer* for academic rules. It does **not** rewire the computation
paths that still hard-code rules via config — Gradebook letter
grades/appreciation/standing, Class Council promotion, Assessment pass-rates.
Those remain config-driven and are tracked as deferred integration (see
Deferred Work). No default policy values are invented: a school that defines no
policies gets exactly the behavior it had with the stubs (`[]`/`null`), so the
sprint introduces **zero behavioral regression** on existing engines.

# Architectural Decision Gate

**Decision: a new bounded context `App\Domains\AcademicPolicy`**, not an
extension of the Academic Framework domain (SPR-002) — policies are an engine
with their own lifecycle, permissions and presentation, mirroring how Gradebook
/ Class Council / Report Card / Academic Communication are separate engines.

Policy types implied by the existing consumers and hard-coded rules:

| Policy type        | Implied by                                    | Status    |
| ------------------ | --------------------------------------------- | --------- |
| `grading_scale`    | AcademicCommunication `GenerateChronicleAction` | implemented |
| `honor_threshold`  | AcademicCommunication `GenerateChronicleAction` | implemented |
| `assessment_rules` | AcademicCommunication `GenerateChronicleAction` | implemented |
| standing thresholds | `config/nexus-gradebook.php` (GPA scale, passing %, distinction %) | deferred |
| promotion rules    | `config/nexus-class-council.php` (passing %, decision defaults) | deferred |
| letter-grade bounds | Gradebook `LetterGrade` / `Appreciation` enums | deferred |

Mandatory now: the engine plus the two **existing** contract consumers (the
only architecturally established integration points). Deferred: rewiring
Gradebook / Class Council / Assessment computation (they have no policy contract
today and are config-driven).

# Policy Inventory & Semantics

- A policy is a **key + label + description + typed value + scope**, owned by
  exactly one school.
- Scopes: `school` (default), `academic_year`, `subject`. A year/subject policy
  is only visible to period-scoped reads matching that year/subject.
- Value types: `string`, `integer`, `float`, `boolean`, `json`. Strict typing:
  a `float` policy is always a float even after the JSON storage round-trip
  (JSON encodes whole floats as ints — normalized on read).
- Keys are unique per `(school_id, key, scope)`.
- `is_active` gates visibility to consumers; archived policies are soft-deleted
  (visible to the audit trail, invisible to queries).
- **No seeding of values.** BF/CI/ML/NE/TG/BJ default rule values are *not*
  invented: schools define their policies through the Filament resource. This is
  the explicit no-default boundary requested by the sprint.

# Design

## Domain layer

- `Domain\Enums\AcademicPolicyScope` — `school | academic_year | subject`
  (labels: École / Année académique / Matière).
- `Domain\Enums\AcademicPolicyValueType` — `string | integer | float |
  boolean | json`.
- `Domain\ValueObjects\PolicyValue` — final readonly; `coerce()` (strict
  normalization from form input) and `fromStored()` (type reapplication after
  the JSON round-trip); rejects mismatched values with
  `InvalidPolicyValueException`.
- `Domain\References\AcademicPolicyReference` — final readonly value object
  exposing `key, label, value, valueType, scope, description, academicYearId,
  subjectId`.
- `Domain\Contracts\AcademicPolicyRepositoryInterface` — `find`,
  `findByKey`, `scopeTaken`.
- `Domain\Contracts\AcademicPolicyQueryContract` — the consumer-facing surface:
  `policies(schoolId, keys)`, `policy(schoolId, key)` (school-scoped, active),
  `forPeriod(schoolId, yearId, termId)` (school + matching year policies).
- `Domain\Events\AcademicPolicyCreated / Updated / Archived` —
  `Dispatchable` + `SerializesModels`, carrying the model and the actor.
- `Domain\Exceptions` — `InvalidPolicyValueException`,
  `DuplicatePolicyKeyException`, `InvalidPolicyScopeException`,
  `PolicyNotFoundException` (all extend `RuntimeException`).
- `Domain\Traits\HandlesAcademicPolicyAuthorization` — typed against the
  `SchoolOwned` contract (same pattern ESP-002 introduced): `super_admin`
  bypass, otherwise same-school + `academic_policy.{action}` permission.

## Application layer

- `Application\DTOs\AcademicPolicyData` — final readonly, `fromArray()`.
- `Application\Actions\CreateAcademicPolicyAction` — validates key/label,
  coerces the value onto the declared type, checks `(school_id, key, scope)`
  uniqueness, persists, dispatches `AcademicPolicyCreated`.
- `Application\Actions\UpdateAcademicPolicyAction` — same checks excluding the
  record itself, dispatches `AcademicPolicyUpdated`.
- `Application\Actions\ArchiveAcademicPolicyAction` — deactivates + soft
  deletes, dispatches `AcademicPolicyArchived`.
- `Application\Services\AcademicPolicyService` — facade over the three actions.

## Infrastructure layer

- `Infrastructure\Models\AcademicPolicy` — implements `SchoolOwned`; `@property`
  PHPDocs for every column/accessor (PHPStan-clean without baseline); `value`
  Attribute accessor normalizing the stored JSON onto the declared type;
  relations to `AcademicCalendarYear`, `AcademicSubject`, creator/updater
  users.
- `Infrastructure\Repositories\EloquentAcademicPolicyRepository` —
  `find`, `findByKey`, `scopeTaken` (all school-scoped).
- `Infrastructure\Contracts\AcademicPolicyQueryAdapter` — maps policies to
  `AcademicPolicyReference`; `forPeriod` merges school-scoped and matching
  year-scoped active policies.
- `Infrastructure\Observers\AcademicPolicyEntityObserver` — ULID `uuid` on
  creating.
- `Infrastructure\Policies\AcademicPolicyPolicy` — `permissionGroup() =
  'academic_policy'`, restore/force-delete denied.
- `Infrastructure\Listeners\AcademicPolicyAuditLogger` — writes an `AuditLog`
  row per lifecycle event (gated by `nexus-academic-policy.policy.audit`).
- `AcademicPolicyServiceProvider` — bindings (repository, query adapter,
  service), `mergeConfigFrom`, observer registration, `Gate::policy`,
  `Event::listen`.

## Persistence

- Migration `2026_08_10_000001_create_academic_policies_table` (anonymous
  class): `id`, `uuid` (ULID, nullable), `school_id` string(36) FK → `tenants`
  cascade, `key`(100), `label`(255), `description`, `value_type`(20),
  `value` (JSON), `scope`(30, default `school`), `academic_year_id` FK →
  `academic_calendar_years` nullOnDelete, `academic_subject_id` FK →
  `academic_subjects` nullOnDelete, `is_active` default true,
  `created_by`/`updated_by` FK → `users` nullOnDelete, timestamps, soft deletes.
  Unique `academic_policies_school_key_scope_unique (school_id, key, scope)`;
  composite indexes on `(school_id, key)`, `(school_id, scope)`,
  `(school_id, academic_year_id)`, `(school_id, academic_subject_id)`.
- Config `config/nexus-academic-policy.php`: `policy.key_max_length`,
  `policy.label_max_length`, `policy.audit`.

# Multi-Tenancy

Every read and write path is school-bound:

- `school_id` is a FK to `tenants` (cascade on delete); the model uses
  `HasSchoolId` (auto-fill from `tenant()?->id` on creating, `scopeForSchool`).
- Repository, query adapter, actions and the Filament resource all scope by
  `school_id`; the resource uses `ScopedByTenant`.
- Duplicate-key and not-found checks are per school: a key used by school A does
  not block school B; a school B actor cannot see or update a school A policy
  (`PolicyNotFoundException`).
- Verified by `AcademicPolicyTenantIsolationTest` and the cross-tenant adapter
  assertion in `AcademicPolicyIntegrationTest`.

---

# Security

- Authorization via `AcademicPolicyPolicy` (`academic_policy.view/create/update/
  delete`); `super_admin` bypasses; non-owners are denied.
- Every policy row records `created_by` / `updated_by` (actor ULID).
- Every lifecycle event writes an `AuditLog` row (school-scoped, type, action,
  actor).
- No mass-assignment surface: fillable columns are explicit; values pass
  through `PolicyValue` validation.

# Limitations

- The engine stores and serves policies but does **not** yet feed the
  Gradebook / Class Council / Assessment computation paths (config-driven).
- `forPeriod` serves school + year-scoped active policies; subject-scoped
  policies are stored and served for explicit keys but are not currently
  consumed by any period-scoped caller.
- The Filament resource provides the management surface; no bulk import/export
  exists yet.
- No seed data: policy values are entirely school-defined by design.
