# ADR-024: Archive & Cloud Storage Platform Architecture (SPR-017)

## Status

Proposed

## Date

2026-10-10

---

## Context

SPR-017 (Archive & Cloud Storage Platform) requires an architecture decision before
any implementation may begin. SPR-017's purpose is the **long-term archive and
retention of official academic records** produced by the SPR-012 (Academic
Communication Engine) substrate and traced by the SPR-014 (Records Lifecycle
Management Engine) envelope, plus — in a later, non-mandatory increment — the
**provision of downloadable school archive packages**.

The SPR-017 discovery / architecture decision board report
(`docs/docs/00_Project_Management/SPR-017_Archive_Cloud_Storage_Decision_Board_Report.md`,
2026-10-10) established the following substrate facts, which this ADR relies upon:

* **No archive implementation exists.** `app/Domains/` contains no `Archive*`,
  `Storage*`, `Backup*` or `Retention*` bounded context; `config/` contains no
  archive/cloud/storage/retention/backup config file; `database/migrations/`
  contains no archive/quota/retention table; `routes/` has no archive route. The
  only storage-related plan column is `plans.storage_limit` (default `'1GB'`)
  (`database/migrations/2026_07_24_000001_create_plans_table.php`).
* **Storage substrate today is local-first.** `config/filesystems.php` defines
  stock `local`, `public` and `s3` disks; the default disk is
  `env('FILESYSTEM_DISK', 'local')`. `s3` is defined but **unused** by any domain.
  `config/tenancy.php` suffixes `local` and `public` per tenant;
  **`s3` is commented out** of the tenant disk list (line 115) and is not
  tenant-aware today. The single document storage switch is
  `config('nexus-academic-communication.disk', env('NEXUS_DOCUMENT_DISK', 'local'))`.
* **Official immutable documents are written today under**
  `documents/{school_id}/{...}-v{n}.pdf` (and `-delivery-{n}.pdf` delivery copies)
  via `Storage::disk(config('nexus-academic-communication.disk', 'local'))`
  (`GenerateDocumentAction.php:212`, `RegenerateDocumentAction.php:88`,
  `PdfExportChannel.php:72`). The `school_id` in the path is a partition key, not
  by itself an authorization proof.
* **The lifecycle substrate SPR-017 consumes is SPR-014.** `RecordLifecycleState`
  expresses exactly three states — `registered | published | archived` — with the
  transition matrix `Registered→Published`, `Registered→Archived`,
  `Published→Archived` (`app/Domains/RecordsLifecycle/Domain/Enums/RecordLifecycleState.php`).
  There is **no** `read_only` or `cold_storage` state; the AD §12 "Cold Storage" stage
  has **no** state representation today. `RecordLifecycleService`
  (`app/Domains/RecordsLifecycle/Application/Services/RecordLifecycleService.php`)
  exposes `register` / `publish` / `archive` / `findBySource`; persistence is the
  `record_lifecycles` table (`school_id`, `source_domain`, `source_type`,
  `source_id`, `source_version`, `lifecycle_state`, `academic_context`,
  `created_by`, `origin_event`, `published_at`, `archived_at`, soft deletes)
  (`database/migrations/2026_08_10_000000_create_record_lifecycles_table.php`).
* **SPR-014 is code-implemented but governance-DEFERRED.** All three source
  domains (Academic Communication, Report Card, Class Council) register / publish /
  archive lifecycle metadata through a `RecordsLifecycleContract` adapter seam
  (`app/Domains/{AcademicCommunication,ReportCard,ClassCouncil}/Domain/Contracts/RecordsLifecycleContract.php`),
  27 integration tests / 97 assertions). Its governance status is **DEFERRED —
  validated implementation awaiting final closure decision**; it must **not** be
  treated as COMPLETE. This ADR consumes SPR-014 **only through its contract
  surface** and does **not** promote, reopen, duplicate or expand SPR-014's scope.
* **Governance intent is already recorded.** `SESSION_HANDOFF` §7 lists SPR-017 as
  an upcoming major sprint; §9 (Active Design Decisions) names long-term archive
  lifecycle, cloud archive service, downloadable school archive packages, storage
  quotas, paid archive extensions; §10 (Pending Decisions) lists **cloud object
  storage provider**. `ARCHITECTURE_DECISIONS.md` §12 defines the archive rule
  (Active → Read Only → Archived → Cold Storage → Retention Policy → Permanent
  Preservation or Secure Destruction; "Official records are never deleted
  directly"). `DEPENDENCY_MAP.md` §10/§13 records that the Records Lifecycle engine
  "never creates business data" and §15 forbids `Archive → Business logic`.
  `RISK_REGISTER.md` tracks OR-004 (storage exhaustion), SA-001 (excessive storage
  consumption), CR-002 (document retention violations). `CHANGELOG.md` v0.4.0-alpha
  expected deliverables include **Academic Archive**; MASTER_ROADMAP Phase 9
  (Enterprise Services) lists **Cloud Archive / Backup / Disaster Recovery** —
  the phase-placement conflict (Phase 3 vs Phase 9) underlying decision D1.
* **Backup is a separate concern.** `docs/08_Deployment/Backups.md` describes
  operational backup scope, schedule, encryption, retention (30d/12w/12m), RTO <2h,
  RPO <15m. Backup is **not** archive: archive/retention is a distinct, legal /
  records-management concern and must **not** duplicate the backup pipeline.
* **The legacy document pipeline is excluded.** `app/Models/GeneratedDocument.php`,
  `app/Models/DocumentTemplate.php`, `app/Services/DocumentGenerationService.php`,
  the legacy `app/Domains/Document/` context, legacy DocumentCenter views and the
  legacy `pdf_enable_qr_code` affordance are deprecated and must not be revived,
  extended or reused — a fixed constraint inherited from ADR-021/022 (L1–L3).
* **ADR numbering.** `docs/ADR/` holds ADR-001 … ADR-022; **ADR-023 is reserved** by
  SPR-016 Phase 6B (`SPR-016_Phase6B_Verification_Issuance_Report.md` §7) for the
  deferred verification-issuance boundary decision. This ADR therefore uses the
  next collision-free number, **ADR-024**. The separate legacy scheme in
  `docs/06_ADR/` is a different convention and is not extended.
* **MariaDB note.** A **pre-existing, unrelated** defect exists: the unique index
  `coefficients_school_id_school_class_id_academic_subject_id_unique` in
  `2026_08_01_000011_create_coefficients_table.php` is **65 characters**, exceeding
  the MySQL/MariaDB 64-character identifier limit. This defect is **not** part of
  SPR-017, is tracked separately, and this ADR neither fixes nor works around it.

Product-owner decisions D1–D5 below were **approved by the product owner
(2026-10-10)** and are recorded here as binding inputs. The remaining technical
choices (boundary, lifecycle interpretation, storage seam, tenancy, retention
mechanism, quota enforcement, package boundary, backup separation) are **proposed
by the architecture team in this ADR**; the ADR remains **Proposed** until the
architecture review accepts it. Unresolved items are enumerated in the
"Open Decisions" section and block specific gates (approval, cloud activation,
first release) as marked.

## Problem Statement

Before implementing SPR-017 the architecture must be decided for:

1. **Scope / phase placement (D1):** is SPR-017 a Phase 3 Academic Records
   deliverable or a Phase 9 Enterprise Services capability?
2. **Storage provider & lock-in policy (D2):** which cloud object storage provider,
   whether an S3-compatible abstraction is mandatory, and whether cloud activation
   is required for the first release.
3. **Archive domain boundary (D3):** is a new bounded context (`App\Domains\Archive`)
   the right shape, consuming SPR-014/SPR-012 only through contracts?
4. **Cold-storage trigger & state model (D4):** does the platform add explicit
   `Read Only` / `Cold Storage` stages, or treat SPR-014 `archived` as the trigger
   with archive provenance held separately?
5. **Retention policy model (D5):** configurable retention by document type and
   school, separating the mechanism from the values; permanent preservation vs
   secure destruction.
6. **Storage quotas & paid extensions (D6):** enforcing `plans.storage_limit`,
   metering, thresholds, and paid expansion — without a second quota authority.
7. **Downloadable school archive packages (D7):** whether in scope, who may
   request, and the security boundary.
8. **Backup vs Archive separation (D8):** archive/retention distinct from
   operational backup.
9. **Tenant isolation of archived objects (D9):** how `school_id` isolation holds on
   any shared storage — in authorization **and** in storage key/path structure.
10. **Legacy pipeline exclusion (D10):** no revival of the legacy generated-document
    pipeline.

This ADR is a **decision-only artifact**: no code, no models, no migrations, no
controllers, no routes, no services, no UI. Implementation is deferred to the
SPR-017 implementation phase and must remain within the constraints recorded below.

## Decision Summary

**SPR-017 is a Phase 9 Enterprise Services capability** (D1, product-approved)
that may be **prioritized for planning now** while its strategic classification
remains Phase 9. Storage is **local-first; cloud storage and every cloud-related
decision are deferred** (D2, product-approved). The archive is a **new bounded
context `App\Domains\Archive`** that consumes source domains and the SPR-014
lifecycle **through contracts only**, never creates or owns business records, never
replaces Records Lifecycle, and records its own archive provenance. The **`archived`
state of SPR-014 is the trigger** for archive entry; this ADR does **not** invent
`Read Only` / `Cold Storage` lifecycle states, which remain an **open decision**.
**Retention policy is configurable per document type and per school**, with the
mechanism built here and the values owned by product/legal; automatic secure
destruction is **disabled by default** and cannot run until legal rules,
authorization and safeguards are confirmed (D3, product-approved). **Quotas reuse
`plans.storage_limit`** as the single authoritative plan limit; SPR-017 creates **no
second quota authority** (D4, product-approved). **Downloadable school archive
packages are in architectural scope but not mandatory for the first release** (D5,
product-approved). Archive and backup remain **separate pipelines**. A single
**S3-compatible storage abstraction** is the proposed seam so the future cloud
activation can be provider-agnostic; no cloud vendor, region, account, credentials
or configuration are introduced by this ADR.

## Decision 1 — Scope & Phase Placement

**Chosen (product-approved D1): SPR-017 is a Phase 9 — Enterprise Services
capability. It may be prioritized for planning now; its strategic classification
stays Phase 9.**

Rationale and consequences:

* The MASTER_ROADMAP Phase 9 module list ("Cloud Archive / Backup / Disaster
  Recovery") is the strategic home of archive. The near-term sprint handoff listing
  of SPR-017 was an **implicit Phase 3 implication, now corrected by this decision —
  reconciled in `MASTER_ROADMAP.md`**. This ADR records that correction.
* "May be prioritized for planning now" means the architecture board may undertake
  SPR-017 planning/ADR work at any time; it does **not** mean archive becomes an
  ordinary Phase 3 academic-records sprint, does **not** change the roadmap phase
  order, and does **not** start implementation without a separate
  implement-readiness decision.
* The consent of Phase 3 deliverables is unaffected: SPR-014 (DEFERRED), SPR-015
  (COMPLETED), SPR-016 (initialization, ADR-022) keep their status.
* SPR-017 planning must not be blocked by any Phase 3 gate; equally it must not be
  used to reopen, accelerate or silently complete SPR-014.

## Decision 2 — Storage Strategy: Local-First, Cloud Deferred

**Chosen (product-approved D2): local-first storage; cloud storage is deferred and
every cloud activation is gated.**

The archive platform's first release **must operate entirely on the existing
local-first substrate** (`local` / `public` tenant-suffixed disks; documents already
stored under `documents/{school_id}/...`). No cloud account, provider, region,
credentials, SDK, config key, IAM policy or infrastructure is created, required or
preconditioned by this ADR.

Consequences and boundaries:

* The archive domain must keep a **decoupled storage seam** (a small storage
  contract/adapter), so a future cloud object-store adapter can be added without
  touching domain logic. The **proposed seam is a single S3-compatible abstraction**
  (Decision 4), consistent with "avoid vendor lock-in" and the already-supported
  `s3` driver.
* **Cloud activation is gated.** Cloud storage may be enabled only when **all** of
  the following conditions hold, recorded in this ADR as the activation checklist:
  1. Product-owner approval of the provider and region (data residency) — currently
     **open** (`SESSION_HANDOFF §10`).
  2. Architecture review acceptance of the S3-compatible seam and the tenant-isolation
     design for shared cloud objects.
  3. Encryption key management and rotation design accepted (see Cryptographic Scope
     — cloud key handling is **open**).
  4. An SLO / availability / cost baseline approved — currently **open** (this ADR
     makes no SLO/cost claim).
  5. The deployment/ops team confirms tenant-aware cloud disk configuration
     (`config/tenancy.php` currently has `s3` commented out of tenant disks).
* Until the checklist is met, "cloud archive" exists only as an abstract,
  provider-neutral capability. **No unsupported availability, durability or cost
  statements are made anywhere in SPR-017.**
* Mixing today's local storage into an "archive platform complete" claim is
  explicitly rejected: local document storage is a substrate, not the archive
  platform (see Context).

## Decision 3 — Archive Bounded Context & Boundary

**Chosen (Architecture proposal): a dedicated bounded context
`App\Domains\Archive`, consuming source domains and SPR-014 through contracts only.**

* The archive owns: archive provenance, retention policy configuration and
  evaluation, archive lifecycle handling, and (later) package generation. It
  **never** creates, mutates or deletes source business records; it **never**
  replaces `RecordsLifecycle`; it holds no copy of the lifecycle engine.
* Consumption pattern: SPR-014 via the `RecordsLifecycleContract` / read surface
  and SPR-012 via approved read/contract interfaces (e.g. document metadata /
  generated-file references). **No direct import of source-domain infrastructure
  models from archive Domain/Application code.** This mirrors ADR-022 C1.
* `Archive → Business logic` remains forbidden (`DEPENDENCY_MAP §15`).
* Boundary rejection options are in Rejected Alternatives.

## Decision 4 — Cold-Storage Trigger & Lifecycle Interpretation

**Chosen (Architecture proposal, partial): SPR-014's `archived` state is the trigger
for archive entry. Explicit `Read Only` / `Cold Storage` lifecycle stages are NOT
introduced by this ADR.**

* The platform's only existing lifecycle signal is
  `RecordLifecycleState = registered | published | archived`. Treating `archived`
  as the archive trigger keeps one lifecycle authority and avoids duplicating
  state machines.
* Archive provenance (when archived, archived_by, source version, pointer to
  archived object) is held by `App\Domains\Archive` as **archive metadata linked to
  the record's `source_*` identity** — it does not extend the `record_lifecycles`
  state vocabulary.
* **Open decision (blocks productionizing granular archive semantics):** whether
  the platform should later add explicit `read_only` / `cold_storage`
  representations to `RecordLifecycleState`. This ADR does not decide it; the
  section "Open Decisions — ODC" below records it, because AD §12's "Read Only /
  Cold Storage" steps have **no** state representation today and must not be claimed
  as existing.
* Consequences of the partial choice: archive may safely run on `archived` records
  immediately; a future lifecycle extension is additive and would be a separate ADR
  (ADR-024 amendment or successor), never a silent modification inside SPR-017.

## Decision 5 — Tenant Isolation of Archived Objects

**Chosen (Architecture proposal): tenant isolation is enforced in authorization
AND in the storage key/path structure; path `school_id` alone is never authorization.**

* **Storage structure proposal:** archived objects live under a per-school prefix,
  e.g. `archive/{school_id}/{...}`, mirroring the existing
  `documents/{school_id}/...` convention; the tenant disk suffix
  (`filesystem.suffix_base` + tenant id) remains the primary tenancy boundary on
  `local`/`public`.
* **Authorization:** every archive read/request is re-checked against the resolved
  tenant/principal via the archive domain's authorization surface; no read trusts
  only the `school_id` embedded in the path.
* **Cross-tenant rule:** no archive operation may address another tenant's prefix or
  tenant disk, and no shared object contains two tenants' data without an explicit
  per-tenant access-control layer (which is **open** for cloud — see Open Decisions).
* This invariant holds for local storage now and is the **mandatory precondition**
  for cloud activation (Decision 2 checklist item 2).

## Decision 6 — Retention Policy Model

**Chosen (product-approved D3 + Architecture mechanism): retention is configurable
per document type AND per school; the mechanism is built; the values are owned by
product/legal. Destruction is separate from preservation and disabled by default.**

### Mechanism vs values

* **Mechanism (architecture, in-scope now):** a retention policy configuration
  driven by **document type** and **school**, evaluated when a record reaches
  `archived`. The mechanism supports, per scope: retention duration, disposition
  class (**permanent preservation** OR **secure destruction**), review/extension
  hooks, and audit of every evaluation/disposition event.
* **Values (product/legal, NOT invented here):** no statutory retention period for
  any document type or jurisdiction (in particular Burkina Faso / Ghana) is
  asserted by SPR-017. Legal/regulatory research is **a separate, named task**
  (see Open Decisions — ODL), not implicit approval of any duration.

### Preservation vs destruction

* **Permanent preservation** and **secure destruction** are **distinct** disposition
  classes. They are not a single toggle: destruction requires more authorization and
  more safeguards than preservation.
* **Automatic secure destruction is DISABLED by default.** No SPR-017 code, config
  or scheduler may delete archived official records outside an authorized,
  auditable, operator-initiated process. Destruction runs only after: (a) legal
  retention rules per document type/jurisdiction are confirmed (ODL), (b) an
  approved destruction authorization + safeguard design is accepted (Open
  Decisions — ODD), and (c) explicit product approval.
* **Compliance claim discipline:** this ADR does **not** claim legal compliance for
  any jurisdiction and does **not** pre-authorize any destruction. CR-002 (retention
  violations) mitigation is the mechanism + gated values.

## Decision 7 — Storage Quotas & Paid Extensions

**Chosen (product-approved D4): `plans.storage_limit` is the single authoritative
plan storage limit. SPR-017 creates NO second quota authority.**

* The archive/quota integration reads the plan authority
  (`plans.storage_limit`), it does not define pricing, thresholds, MB/GB values, or
  SLA red-lines.
* **Distinction required:** plan limits (the authoritative *capacity* a plan grants)
  are distinct from *storage metering* (measuring actual usage), which is **not**
  implemented and remains open (see Open Decisions — ODQ). Both are distinct from
  paid-extension *pricing/commercial enforcement* (also open — ODQ).
* RISK SA-001 mitigation ("storage quotas and paid plans") is served by this
  decision's integration, **without** inventing quota values, prices, thresholds or
  billing rules.
* Rejected: a dedicated quota store (see Rejected Alternatives) — would make
  SPR-017 a second quota authority.

## Decision 8 — Downloadable School Archive Packages

**Chosen (product-approved D5): downloadable school archive exports are in
architectural scope but NOT mandatory for the first release.**

* **In scope now (boundary and security design):** define the capability —
  tenant-scoped, request-authorized, auditable, completeness + integrity checked,
  controlled access, with expiry and cleanup and safe failure behavior. The
  **security boundary** is fixed at this ADR level:
  * **Authorization:** only principals granted the archive-export capability may
    request a package; request = explicit actor + reason + time window.
  * **Strict tenant isolation:** a package contains exactly one school's records;
    cross-tenant inclusion is prohibited (Decision 5 extends to package contents).
  * **Auditability:** every request, generation and delivery is an auditable event.
  * **Integrity & completeness:** packages carry a manifest with verification
    hashes; incompleteness fails loudly, never silently.
  * **Expiry & cleanup:** packages are temporary artifacts with an expiry and are
    cleaned up; delivery is not a defensible permanent store.
  * **Safe failure:** a failed package generation yields no partial "success"
    artifact and is retryable.
* **Out of scope until a later release:** package generation/download routes, UI,
  jobs, persistence, formats, contents listing, max sizes, retention/expiry values,
  permission surface — all itemized as **open** (Open Decisions — ODP). The
  architecture does **not** commit formats/contents/size/retention.
* First release = local archive + retention mechanism + quota authority integration;
  packages add no first-release dependency.

## Decision 9 — Backup vs Archive Separation

**Chosen (Architecture proposal): archive/retention is distinct from operational
backup; no duplication of the `Backups.md` pipeline.**

* Backup (scope, schedule, encryption, 30d/12w/12m retention, RTO/RPO) remains the
  ops-owned operational recovery pipeline (`docs/08_Deployment/Backups.md`). Archive
  is records-management: authoritative, long-term, retention-policy driven, with its
  own provenance and (future) export.
* SPR-017 creates no backup schedule, no snapshot machinery and no recovery SLO; it
  must not shadow the backup team's RTO/RPO obligations.
* Documents that are archived **remain covered by operational backup** (archive is
  not a removal-from-backup signal), but backup retention is **not** the archival
  retention mechanism.
* (Pre-existing doc inconsistency noted, out of scope: `Backups.md` states
  "PostgreSQL" while PROJECT_STATE declares MySQL. Not touched here.)

## Cryptographic Scope

Decision-only; no library or key material is committed by this ADR.

* **At-rest integrity for archived records:** archived objects must carry a
  verifiable content digest (mirroring `content_hash` / `GeneratedFile.checksum`
  precedent) so integrity survives moves between storage layers; the digest proves
  integrity, not authenticity.
* **Authenticity/provenance:** the archive metadata links to the source record's
  lifecycle identity and to the platform's existing versioning; archive provenance
  is metadata, never a new "official record" claim.
* **Encryption at rest / in transit (local):** follows the existing platform
  defaults; this ADR names the requirement (encryption of archived artifacts) but
  does not introduce a new key-management system.
* **Cloud key handling is OPEN (ODC2 in Open Decisions):** cloud encryption-key
  management and rotation (platform-held vs school-held keys, tenant key separation)
  is deliberately **not** decided here and blocks cloud activation (Decision 2
  checklist item 3). No SLO/availability/cost claim is made (Decision 2 item 4).
* **Signing/electronic-seal requirements for packages** are **open** (ODP); no
  signature primitive is assumed.

## Security Invariants

* **S1 — No cross-tenant archive access:** every archive operation resolves a
  tenant and never addresses another tenant's objects; `school_id` in a path is
  never authorization by itself (Decision 5).
* **S2 — Archive never mutates source records:** the archive domain reads through
  contracts and writes only its own provenance/retention metadata.
* **S3 — No unauthorized permanent deletion:** automatic secure destruction is
  disabled; deletion only via an authorized, auditable, operator-initiated path.
* **S4 — Integrity checkable:** archived objects and (future) packages expose
  verifiable manifests/digests; silent partial data is impossible by design.
* **S5 — Audit:** archive entry, retention evaluation, disposition and any package
  request/generation are auditable events.
* **S6 — No cloud capability, no SLO claim:** nothing in SPR-017 asserts cloud
  provision, durability, availability or cost that is not gated and approved.
* **S7 — Legacy exclusion:** nothing in SPR-017 reads or writes
  `app/Models/GeneratedDocument`, `app/Models/DocumentTemplate`,
  `app/Services/DocumentGenerationService`, legacy `app/Domains/Document` or legacy
  DocumentCenter / `pdf_enable_qr_code`.

## Lifecycle Invariants

* **L1 — One lifecycle authority:** SPR-014 remains the single lifecycle authority.
  SPR-017 never registers/publishes/archives lifecycle state on source records.
* **L2 — `archived` is the only archive trigger:** only `RecordLifecycleState::Archived`
  records enter the archive pipeline; unpublished/live states are not archived.
* **L3 — No invented states during execution:** the running engine never assumes
  `read_only` / `cold_storage` states exist (they do not); the ODC decision gates
  any future representation.
* **L4 — SPR-014 status preserved:** this ADR does not mark SPR-014 COMPLETE and
  does not reopen it; interlock = contract-only consumption.
* **L5 — Archive provenance is separate:** archive metadata (when/how/source
  version) lives in `App\Domains\Archive`, never inside `record_lifecycles`.

## Tenancy Invariants

* **T1 — Per-school object prefix + authorization:** archived paths are

* **T2 — Tenant disks remain the primary boundary on local/public:** the existing

## Consequences

Positive:

* Local-first launch is possible without any cloud dependency, preserving the
  current green/no-infrastructure posture.
* Retention is a genuinely configurable mechanism per document type and school,
  ready for legal values without code change.
* A single quota authority keeps plan semantics authoritative and avoids a second
  billing/quotas story.
* The cloud seam keeps provider choice open and activation reversible; no lock-in
  decision is forced today.
* SPR-014 boundary is respected: archive is additive and contract-only.
* Packages are designed as secure, auditable, tenant-isolated capability from the
  start, even if deferred.

Negative / acceptance:

* Cloud capacity (durability, availability, cost, key rotation) is **not** available
  at first release — that is an accepted consequence of local-first.
* Retention values and destruction authorization remain unresolved by design; the
  mechanism cannot enforce durations that product/legal has not approved.
* No metering/no quota hard enforcement exists until ODQ is resolved; storage
  growth is governed by plan limits only.
* An "archive" that is local disk is operationally distinct from a resilient
  archive; this is accepted and disclosed, not masked.
* The D1 phase-placement correction means SPR-017 is strategic (Phase 9): near-term
  sprint planners must not treat it as an ordinary Phase 3 deliverable.

## Rejected Alternatives

1. **Extending `RecordsLifecycle` in place to host archive semantics (D3/B)** —
   rejected: violates SPR-014's thin-lifecycle scope and risks duplicate lifecycle
   ownership. Archive is a new bounded context.
2. **Platform service outside Domains (D3/C)** — rejected: weakens DDD/contract
   discipline and the DEPENDENCY_MAP §13 shape.
3. **A dedicated quota store (D6/B)** — rejected: duplicates the plan authority;
   `plans.storage_limit` remains the single source of truth (product-approved D4).
4. **Cloud-first / cloud required for first release (D2)** — rejected
   (product-approved D2): no cloud dependency, no unsupported SLO, decoupled seam.
5. **Hard-coded single cloud vendor SDK as the only storage path (D2/C, D9)** —
   rejected: creates lock-in and breaks the provider-agnostic check on the
   activation gate.
6. **Auto-destruction enabled by default under retention policies (D5)** —
   rejected: no legal values, no authorization/safeguard design; destruction stays
   off until ODL/ODD close.
7. **Statutory retention defaults invented by architecture (D5)** — rejected:
   legal/regulatory research is a separate task; architecture does not set law.
8. **`school_id`-in-path as sufficient isolation for archive reads (D5/D9)** —
   rejected: every read is re-authorized; path alone is never a capability.
9. **Packages mandatory in first release (D7/D5)** — rejected (product-approved D5):
   boundary/security defined now, implementation deferred; no format/contents/size
   commitments.
10. **Reviving legacy `GeneratedDocument` / `DocumentTemplate` /
    `DocumentGenerationService` / `app/Domains/Document`** — rejected: fixed
    constraint (LG1), mirrors ADR-021/022 L1–L3.
11. **Reusing the backup pipeline as the retention mechanism (D8)** — rejected:
    backup is operational recovery; retention is records management.

## Implementation Constraints

Contract obligations placed on the future SPR-017 implementation:

* **C1 — Contract-only reads:** archive Domain/Application must not import
  source-domain infrastructure models (mirrors ADR-022 C1; Dependency_Inversion).
* **C2 — No lifecycle writes:** archive never calls `RecordLifecycleService` to
  mutate state (L1); it only reads.
* **C3 — Tenancy discipline:** per-school prefixes + authorization on every read
  (Decision 5, T1–T2).
* **C4 — Storage seam:** a narrow storage contract/adapter behind which the local
  implementation is replaced later by an S3-compatible adapter.
* **C5 — Retention evaluation is value-driven:** durations/dispositions come from
  configuration store, never hard-coded; unconfigured ⇒ no destruction, no assumed
  period.
* **C6 — Quota integration reads `plans.storage_limit`; no second quota table.**
* **C7 — No package machinery in first release:** no routes, UI, jobs, or package
  persistence until ODP closes.
* **C8 — Audit:** archive entry, retention events and any disposition/request are
  auditable events with actor + timestamp + scope.
* **C9 — No cloud config/credentials/SDK/dependency:** strictly local until
  Decision 2 checklist is fully approved.
* **C10 — APP domain name `App\Domains\Archive`** (unless a later architectural
  review renames it before implementation; rename before code, not after).

## Future Extension Boundaries

* **Cloud object-store adapter:** activated only via the Decision 2 checklist; the
  seam is provider-neutral.
* **Lifecycle `read_only` / `cold_storage` states:** additive, governed by ODC,
  requires a lifecycle-authority amendment (ADR-024 successor or amendment) — never
  a silent SPR-017 extension.
* **Package generation/download:** built on the Decision 8 boundary when ODP
  closes; a separate release.
* **Paid archive extensions & metering:** new capability after ODQ; the quota
  authority stays `plans.storage_limit`.
* **Government/regulator archive-compliant features (e.g. e-archival certification):**
  separate ADR; nothing here ties SPR-017 to a specific regulator.
* **Automated retention enforcement with real values:** after ODL/ODD; automatic
  destruction remains OFF until then.

## Testing Requirements

During SPR-017 implementation (tests are out of scope for this decision phase; the
ADR is decision-only):

* **Tenant isolation:** school A cannot read, list, request or receive any archive
  artifact of school B; path `school_id` misdirection is rejected by authorization.
* **Trigger correctness:** only `archived` lifecycle records enter the archive;
  registered/published records never do.
* **Retention matrix:** per-document-type + per-school durations/dispositions
  evaluate as configured; unconfigured scopes default to no-destruction/no-period.
* **Destruction safety:** with auto-destruction disabled, no test can produce a
  deletion of an archived record absent an authorized operator action.
* **Quota authority:** quota checks read `plans.storage_limit`; no second quota
  table/authority exists.
* **Integrity:** archived object digests/manifests verify; tampered objects fail
  verification loudly.
* **Backup separation:** SPR-017 introduces no backup schedule/snapshot machinery.
* **Legacy exclusion:** architecture tests assert no import of legacy documents.

Full-suite requirement, PHPStan, and Pint gates apply at implementation time per
the project's ACME discipline; no tests are run for this decision-only phase.
